# 单机风洞实验平台设计

用户已在对话中确认 B 路线，先在一台电脑运行网页、后台任务和设备适配器，并授权直接开发。

## 已确认范围

- 多测点目标平均风速匹配，可选湍流度目标及翼板。
- LangGraph 管理有界 ReAct 循环，模型上下文承担短期对话，checkpoint 保存执行位置，数据库记录实验与操作事实。
- React 网页用于配置、进度、决策摘要、工具参数与结果、日志下载、暂停继续和取消。
- 设备工具与分析、控制策略分层。第一版分析提供统计及目标误差、图表。策略先采用反馈修正，预留统一替换接口。
- 长期经验含项目、标定版本、证据、适用条件、状态。实测事实与候选经验分开，分析产物可关联入库。
- 王凯的 set_fan_field(spec) 接收风场原语，负责展开、档位换算与串口。华航热线使用已有采集代码的调用适配器。

## 方案与实现决定

A 为单进程闭环，B 为有任务与操作边界的后台平台。用户选择 B，先单机。采用 FastAPI、SQLite、LangGraph SQLite checkpoint 和 React。网页由同一个服务提供，本地监听 127.0.0.1。后台使用单个串行执行器，单进程独占运行目录，避免两个实验同时控制设备。

第一版默认模拟设备，可选注入 Python 设备适配器。模拟读数不代表物理实验验证。设备执行结果未知时暂停并等待核对，禁止自动重复动作。任务恢复在每个测点和工具操作边界进行。暂停与取消在工具边界生效，调用中的硬件动作由设备适配器的超时及停止接口负责。

风扇矩阵索引和探针毫米坐标显式分开。静态目标逐点扫描，时变同步留作扩展。A/B 类剖面需要用户提供指数与物理高度映射，不硬编码规范。第一版不实现未经确认的强化学习算法。

## 工具层次

- devices，set_fan_field、set_flap、move_probe、measure_hotwire。
- analysis，analyze_field，内部统计、误差和生成 SVG 数据图表。
- control，propose_adjustment，内部策略接口，不把每个数值函数暴露为工具。

模型通过类型化工具调用选择动作，数值验收和合法顺序由代码约束。默认反馈策略可离线运行，DeepSeek 模式使用真实模型调用并展示显式决策摘要。工具错误有可定位日志。

## 数据与恢复

任务介绍、目标、状态、进度、事件、操作、轮次结果、经验保存 SQLite。每次操作先记录意图，再调用设备，最后记录结果。同一操作编号参数必须相同。恢复复用已完成操作；pending/unknown 必须通过设备适配器查询，人工确认后以新任务继续也可。

原始采样文件保存于各任务目录，checkpoint 和上下文仅保存摘要及路径引用。分析记录保存采样率、均值、标准差、湍流度、样本数、误差和数据来源。长期检索先按项目、设备与标定版本过滤。

## 验收

运行旧测试与新平台测试。新测试覆盖原语校验、统计有效性、多轮收敛、模型工具循环、记忆检索隔离、暂停取消与重启恢复、操作去重及未知结果、API 和网页资源。通过真实 HTTP 与浏览器验证页面及模拟实验。
