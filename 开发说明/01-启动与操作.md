# 01 启动与操作

## 本机启动

本次开发建立了 `.lab-venv`，原有 `.venv` 的文件继续保留。从项目根目录运行。

```bash
.lab-venv/bin/python -m labagent
```

浏览器打开 [工作台](http://127.0.0.1:8765)。关闭终端里的服务会停止提供网页，关闭浏览器页面则后台实验继续执行。

可指定端口和数据目录。

```bash
.lab-venv/bin/python -m labagent --port 8766 --data-dir lab_data
```

默认监听本机 127.0.0.1，采用单进程，一个数据目录只允许一个服务实例。同一时间只运行一个实验，暂停或结果待核对的实验也占用该实验通道。

## 换一台电脑安装

准备 Python 3.11 至 3.14 之间的版本。推荐使用 uv 创建环境并安装 `pyproject.toml` 声明的依赖。

macOS 或 Linux 示例。

```bash
uv python install 3.13
uv venv .lab-venv --python 3.13
uv pip install --python .lab-venv/bin/python -r pyproject.toml --extra test
.lab-venv/bin/python -m labagent
```

Windows PowerShell 示例。

```powershell
uv python install 3.13
uv venv .lab-venv --python 3.13
uv pip install --python .lab-venv/Scripts/python.exe -r pyproject.toml --extra test
.lab-venv/Scripts/python.exe -m labagent
```

uv 的安装方法见 [官方安装文档](https://docs.astral.sh/uv/getting-started/installation/)。网页所用的 React 18.3.1 已随项目保存在 `labagent/web/vendor/`，初次安装 Python 依赖完成后，离线基线模式可在断网环境运行。当前机器验证了 macOS，Windows 安装步骤仍需在目标电脑验证。

## 第一次实验

1. 保持“离线反馈基线”模式。
2. 使用默认四测点示例，或者修改每个测点的目标风速。
3. 点击“启动实验”。
4. 观察轮次、扫描进度和误差。
5. 在“执行记录”中展开决策摘要、风场设置、探针移动和热线采集的参数及返回值。
6. 查看目标与实测图表、湍流度与误差趋势。
7. 点击“下载实验包”和“下载日志”。

默认模拟器以简化的风扇响应和正弦脉动生成读数，采样在计算机上即时生成，因此模拟耗时可以短于所声明的采样时间窗。

## 参数含义

| 参数 | 含义 |
|---|---|
| `description` | 实验介绍、已做工作和本次意图，进入模型上下文并保存 |
| `x_mm`、`y_mm` | 探针物理坐标，单位毫米 |
| `fan_x`、`fan_y` | 该测点对应的风扇列、行索引，反馈基线使用此映射 |
| `target_mps` | 测点目标平均风速 |
| `target_ti` | 可选目标湍流度，0.1 表示 10% |
| `tolerance_mps` | 每个测点允许的绝对风速误差 |
| `tolerance_ti` | 湍流度比例允许的绝对误差 |
| `settle_seconds` | 设置控制参数后、开始扫描前的稳定等待 |
| `sample_count`、`sample_rate_hz` | 每个测点的采样数量与采样率 |
| `max_iterations`、`max_seconds` | 轮数与累计执行时间预算，暂停等待不计入累计执行时间 |
| `max_speed_mps`、`max_change_mps` | 控制参数上限与单轮风速参数变化上限 |
| `device_id`、`calibration_version` | 设备和标定标识，控制长期检索适用范围 |

第一版映射要求各测点对应不同风扇单元。物理设备的实际运动范围、稳态时间、采样约束和通信超时由设备适配器进一步校验。

## 高级配置

展开“高级参数”，点击“载入当前配置”，修改 JSON 后点击“应用 JSON”，随后启动新实验。可将 [完整示例](示例/左右不同风速.json) 复制到输入框。

可选翼板配置示例如下。

```json
{"angle_deg":0,"amplitude_deg":5,"frequency_hz":1}
```

把它写入完整配置的 `flap` 字段即可。离线基线会应用这组固定翼板参数，并评价湍流度目标。基线的自动修正只针对平均风速，自动改变翼板参数需要使用模型决策或后续联合控制策略。

## DeepSeek 模式

在项目根目录 `.env` 中配置以下变量，网页选择 DeepSeek ReAct 后启动新实验。

```dotenv
DEEPSEEK_API_KEY=填写你的密钥
DEEPSEEK_MODEL=deepseek-chat
```

模型会收到实验介绍、目标、当前统计、最近工具结果及同项目同设备同标定的历史证据。每步调用真实模型，存在 API 延迟与费用。密钥从后端读取。

离线反馈模式采用确定性决策，适合先检查接口和数据流。DeepSeek 模式共享相同设备校验与数值验收。工具调用协议已完成注入模型测试，并使用当前账户配置完成了真实 DeepSeek 的六轮模拟闭环。详情见 [前端演示](05-DeepSeek前端演示.md)。

## 暂停、继续与停止

- 暂停请求在工具或测点边界生效。已进行的采样与运动需等设备返回。暂停保持当前控制设置。
- 继续从 checkpoint 恢复，已完成的移动和采样复用操作日志中的结果。
- 停止请求在工具边界处理，调用适配器的 `stop()`，确认后显示“已停止”。
- 达标或预算结束也会调用 `stop()`，设备停止确认后才提交终态。
- 停止失败会显示“需要核对”。后续继续会先恢复待确认的停止操作。
- 动作结果未知时会显示操作编号。核对后继续时，适配器须能够查询该操作的可信结果。仍未知时继续保留待核对状态。
- 服务重启后，未结束实验显示为暂停。核对实际设备状态后再继续。

网页事件窗口显示最近记录，下载日志保留完整事件历史。SSE 事件流提供递增序号，网页断连后可继续补读。

API 的交互式文档位于 [本地 API 文档](http://127.0.0.1:8765/docs) 。
