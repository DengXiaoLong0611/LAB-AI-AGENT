# 04 验证与后续开发

## 本轮验证结果

验证环境为 macOS ARM64、Python 3.13.18。所有命令在项目根目录执行。

```bash
.lab-venv/bin/python -m unittest discover -s tests -v
.lab-venv/bin/python -m compileall -q labagent
```

本轮共 39 项测试通过，覆盖原有电机解析、记忆与思考模块，以及新平台的组件、恢复和 API。

新增平台测试重点覆盖以下情形。

| 类别 | 验证内容 |
|---|---|
| 原语 | 图层覆盖、矩形越界、非有限风速与测点索引 |
| 分析 | 均值、脉动、湍流度、零均值、坏样本、缺失测点 |
| 控制 | 反馈方向、单轮变化限幅、模拟多轮收敛 |
| 操作日志 | 已完成操作去重、参数冲突、超时后的未知结果 |
| 恢复 | 扫描中暂停、重建执行器继续、已采样点去重 |
| 崩溃窗口 | 设备操作完成而图尚未 checkpoint 时的模拟器恢复 |
| 停止 | 开始前停止、停止未确认、达标后停止、恢复待停止操作、设备重连失败保留停止意图 |
| 并发请求 | 最终分析及停止确认期间接受取消，取消意图保持优先 |
| 终态数据 | 停止前持久化最终分析，防止恢复后遗漏最终结果 |
| 模型接口 | 注入聊天模型，检查真实 tool_calls 解析与可用工具约束 |
| 长期记录 | 实验与经验入库、项目范围隔离与证据引用 |
| API | 创建任务、网页静态资源、错误输入、工具调试、日志与实验包下载 |

另进行了新 Python 文件的 Ruff 基础错误与导入检查，以及 React 页面 JavaScript 的语法检查。

## 当前交付范围

| 部分 | 当前形态 |
|---|---|
| 部署 | 本机单进程服务，API 与一个后台线程分工 |
| 前端 | React 本地静态资源，支持实验、工具和记忆页面 |
| ReAct | 离线反馈模式与 DeepSeek 工具调用模式共享图和约束 |
| 设备 | 默认模拟器，以及可注入已有 Python 程序的回调适配器 |
| 控制 | 映射单元上的限幅比例反馈 |
| 分析 | 平均风速、总体标准差、湍流度、目标误差、SVG 和 CSV |
| 记忆 | 关键词检索、设备与标定范围过滤、候选经验状态 |
| 恢复 | 本地 checkpoint 与操作日志，未知动作先查询 |

## 需要实机继续验证的内容

- 王凯的实际原语 schema、风扇数量、安装方向、速度标定与通信接口。
- 龙门架的坐标范围、到位判断、移动后探针稳定时间与回零方式。
- 华航程序的采样接口、实际返回格式、标定版本和数据质量标志。
- 翼板实际可用角度、振幅、频率及其对均值与湍流度的耦合。
- 断连、动作超时、停止确认、网关重启以及操作编号的持久查询。
- DeepSeek 在不同实验配置及真实设备反馈下的决策效果与延迟。

首次开发验证使用模拟设备和可注入模型。随后通过 DeepSeek 真实接口完成了六轮前端实验，详情见 [前端演示](05-DeepSeek前端演示.md)。反馈基线的收敛只反映当前简化模拟器的行为。真实装置的可达性和控制效果需要实验标定。

当前应用以明确的测点目标和 JSON 参数启动任务，自然语言研究助手和由自由描述自动构建完整实验配置可以在后续接入已有聊天能力。

## 后续扩展顺序

1. 与王凯对齐共享原语 schema，接通单区风扇、单测点热线和龙门架。
2. 根据实测建立坐标映射、风扇响应与气动耦合基线，验证多测点反馈。
3. 把翼板与湍流度加入联合控制，记录各统计量的采样稳定性。
4. 增加频谱、FFT、滤波和数据质量分析，仍通过统一分析工具调用。
5. 按实验需要接入贝叶斯优化、系统辨识或其他控制策略，并保存算法版本。
6. 设计可重复时序与采样同步，再发展时变目标场。
7. 逐步增加 PIV、跨电脑设备执行端和长期向量检索。

在单根探针顺序扫描时，各点对应不同采样时刻。静态场以相同稳态工况比较。时变空间场需要相位同步或重复实验设计。

## 原设计资料的取舍

本轮从蓝图中采用了任务、操作、产物、checkpoint 和经验的分离，受约束实验闭环、分层工具、数值验收、未知结果查询以及数据可追溯。

后台队列目前由单执行线程承担，事务由 SQLite 管理。多机分布式执行、PIV/RPA、消息代理、向量库与强化学习训练适合放在后续已有实验数据和接口验证的阶段。
